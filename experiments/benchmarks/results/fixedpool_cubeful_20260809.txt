# ORDER NOTE (Sage cube row): Sage-1ply cube measured 16.63 ms (Zen5) when
#   run immediately after the Sage-0ply rows' ~2 min of sustained single-core
#   load, vs 14.80 ms standalone (matching the 2026-08-02 and 2026-08-05

#   with tight within-run CIs. Committed values are from the
#   light-prior-load condition, the same condition as every other row.
# SAGE CUBE IS FIXED-OVERHEAD-BOUND: its 0-ply cube call costs nearly as much
#   as its 1-ply one (28.18 vs 29.17 ms Zen3; 11.24 vs 14.80 Zen5) — the cube
#   machinery, not net evaluation depth, dominates (matches the self-play
#   finding that Sage's cubeful cost is cube-bound). Its 1-ply cube primitive
#   is ~70x gnubg's (29.17 vs 0.4196 ms, Zen3).
# CUBE-STATE NOTE: per-position cube states matter — measured directly
#   (3000 boards, Zen3, 1-ply cfevaluate, 2026-08-05 microbenchmark, not
#   re-run): centered 0.409 ms vs owned-at-2 0.385 vs owned-at-4 0.337
#   (0-ply: 0.0045 vs 0.0025). Recube evaluations are CHEAPER, so a
#   constant-centered convention would overstate gnubg's cube cost; the
#   shared pool avoids the approximation.
# These are ISOLATED primitive costs: for cache-reusing engines (gnubg, Sage)
#   they overstate the amortized in-play cube cost — in real play the pre-roll
#   cube evaluation shares its lookahead leaves with the same turn's move
#   search and prior turns' analysis (gnubg self-play marginal cube cost at
#   1-ply is 0.150 ms vs 0.4196 ms here). The self-play table is the amortized
#   comparison; the two methodologies bracket real cost.
# Zen3->Zen5 ASYMMETRY (PureTD cube 4.0x vs checker 2.6x) is real, not an
#   artifact — verified by direct microbenchmark on idle boxes (2026-08-05,
#   not re-run): the cube op is a BATCH-2 forward (offer_double evaluates the
#   no-double + double-take perspectives in one 2-row batch,
#   td_agent.offer_double), and the bare batch-2 net forward measures 149us
#   Zen3 vs 37us Zen5 = 4.0x (small-batch GEMV is vector-width/overhead-bound:
#   Zen5 has AVX-512 + higher IPC + DDR5 bandwidth; Zen3 is AVX2 — Zen5
#   batch-1 and batch-2 cost the SAME 37-38us, i.e. fully overhead-bound),
#   while batch~20 checker forwards ratio only 2.25x (GEMM-efficient on both)
#   plus ~1.7x-scaling C move-gen. Self-play attribution corroborates
#   independently: cube 0.237 (Zen3) vs 0.070 (Zen5) = 3.4x against checker
#   0.406 vs 0.155 = 2.6x — the attributed cube cost is a small difference of
#   large wall-clocks and so noisier than the fixed-pool figure, but it puts
#   the cube ratio well above the checker ratio by both methods.
