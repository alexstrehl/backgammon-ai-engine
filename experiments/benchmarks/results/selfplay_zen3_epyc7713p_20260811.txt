# Zen 3 (EPYC 7713P), core 100, idle, one pinned core, 2026-08-11.
# FIVE independent sweeps of bench.sh (SWEEPS=5), each a fresh process with
# a 90 s idle gap so sweeps sample independent thermal states. Every engine in
# a sweep is timed on the SAME core: that is what makes the per-engine costs
# comparable. The absolute values characterise this core, not the processor --
# per-core frequency binning spreads throughput ~10% on Zen 5.
#
# Game counts are tiered by MEASURED per-game cost, not by search depth
# (ply is a poor proxy: Sage's 0-ply analyzer costs 0.70 s/game, 10x gnubg at
# 1-ply). G_FAST=600 for everything under ~100 ms/game; G_SLOW=200 for the two
# Sage analyzer rows.
#
# Each row: mean of the 5 sweeps, 95% t-interval OVER SWEEPS (t(4)=2.776), and
# the 5 raw values so the interval is recreatable. The per-sweep bootstrap CIs
# are NOT used here -- they describe how precisely one run was measured and
# cannot see run-to-run variation, which is the larger term. Do not pool raw
# per-game points across sweeps: games in a sweep share its thermal state.
#
# Regenerate: SWEEPS=5 BENCH_CORE=<n> VENV=<py> bash experiments/benchmarks/bench.sh
#             python experiments/benchmarks/aggregate_sweeps.py $OUTDIR/bench_<host>_sweep*.txt
# Raw sweep logs (~330 KB each, mostly gnubg per-game score lines) are archived
